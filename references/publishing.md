# 发布与分享

把分享副本（纯静态网站：`index.html` + `memories/` + `music/` + `flip.mp3`）发布成一个链接，别人打开就能看。

**做好网页、用户在本机看过之后，要主动问一次要不要发布**，但不替用户决定：
> 要不要把它发布成一个链接，发给朋友或家人看？发布后，能打开链接的人就能看到里面的照片和文字，也能把照片存下来。想发的话，我先生成一份去掉定位信息的分享副本给你过目。

用户没有明确说要发布，就只在本机看。

## 0. 选平台（按顺序判断）

| 顺序 | 情况 | 用什么 | 体积上限 | 生成副本时 |
|---|---|---|---|---|
| 1 | 你运行在**豆包**里 | 豆包自带的网页发布（链接是 `doubao.link`，或 `feishu.link` = 发到了飞书妙搭） | **50MB** | `--budget-mb 48` |
| 2 | 其他宿主，**自带发布网页的功能** | 宿主自带的发布功能 | 按宿主的限制 | `--budget-mb <上限减一点>` |
| 3 | 没有自带发布功能，或者体积超过上面的上限 | **EdgeOne Makers**（腾讯云） | 宽松 | `--out ~/时光手帐/share-edgeone` |
| — | 不在豆包里，但用户明确要发到飞书 | 飞书妙搭，用 lark-cli（见 D 节），链接也是 `feishu.link` | 打包后 20MB | `--budget-mb 19` |

- **怎么判断“自带发布功能”**：看你当前可用的工具（包括要先加载的延迟工具）里，有没有用来发布、部署网页或分享页面的。名字或说明里常带 publish、deploy、artifact、share、发布、部署、网页托管。
  - 这个功能要能发布**多个文件**（一个文件夹，或者 `index.html` 加同目录的附属文件），或者能直接收 `share.zip`。
  - 只能发布单个 HTML 文件的不行：照片和数据是单独的文件，发上去会缺。
- 用了哪个平台、为什么选它，发布前告诉用户一句；用户想换平台就换。
- 体积超了，不要只说“发不了”。按上面的顺序往下换平台，或者让用户选：
  - 缩小范围（`--years`）；
  - 去掉音乐（`--no-music`）。

## 1. 确认范围，生成分享副本（所有平台通用）

先一次问清：
- **分享哪些**：默认全部。可以只要某几年、去掉某几段、不带正文、不带地点。
- **背景音乐**：默认带上。提醒一句歌曲可能有版权；用户不想带就加 `--no-music`。

```bash
python3 $S/scripts/build_share.py --project ~/时光手帐 --budget-mb <按平台> [--years 2019 2020] [--exclude <回忆id> …] \
    [--no-text] [--no-place] [--no-source] [--no-music] [--zip]
```

副本放在 `~/时光手帐/share/`（EdgeOne 单独用 `share-edgeone/`），本机项目不改动。副本已经做了这些处理：
- 照片去掉了 GPS 定位、相机型号等元数据，只保留照片方向；
- 编号全部重排，原文件名和平台编号都不带出去；
- 不带任何本机文件；
- 加了 noindex。

给了 `--budget-mb` 时，超了会自动把照片缩小、压低画质（`SHRINK` 行），最多缩到长边 800。还放不下时输出 `BUDGET over`，并给出照片和音乐各占多少。这时按第 0 步换平台，或者让用户缩小范围。

**发布前给用户过目**，这一步不能省：
1. 原样告诉用户：多少段回忆、多少张照片、年份分布、多少段带文字或地点、带几首音乐、压缩后多大。
2. 每一条 `CHECK` 逐条问用户要不要去掉。`CHECK` 是文字里疑似手机号、身份证号、邮箱、@别人、门牌地址的地方。要去掉的，用 `--exclude <id>` 或 `--no-text` 重新生成。
3. 你能看图的话，提醒用户留意照片里的这些内容，由用户决定：
   - 别人清楚的正脸，尤其是孩子；
   - 证件、车牌；
   - 截图里的聊天内容。
4. 可以先在本机预览：`python3 $S/scripts/serve.py --project ~/时光手帐/share`。

**所有平台都适用的规则：**
- 最终确认时用一句话说清：平台、范围、谁能看。用户说“发吧”再发。
- 账号登录、实名认证都由用户本人在官方页面完成。不要密码、令牌、Cookie，也不读取、复述、保存工具存下的凭据。
- **只报平台真实返回的链接**，原样完整地给出，不截断、不改写、不编造。
- 发布后告诉用户三件事：链接、谁能打开、以后怎么更新和撤下。也要说明：别人已经存下来的照片收不回来。

## A. 豆包自带的网页发布

你在豆包里运行、并且有它的网页发布功能时，优先用它。

1. 用 `--budget-mb 48` 生成副本。豆包网页发布上限是 50MB，留一点余量。
2. 按豆包的发布功能要求上传：能传文件夹就传 `share/` 整个文件夹；只收压缩包就加 `--zip`，传 `share.zip`。
3. 发布成功后会得到链接，原样给用户：
   - `doubao.link`：豆包的网页链接，谁能看以豆包的说明为准；
   - `feishu.link`：其实是发到了**飞书妙搭**，和 D 节是同一个平台。妙搭默认可能只有创建者自己能打开，要给别人看，请用户在妙搭网页端 → 我的应用 → 可见范围里设置（见 D.3）。
   - 不要只靠链接的域名去猜谁能看，先如实告诉用户“可能只有你自己能打开”，请他用别的账号或无痕窗口试一下。
4. 超过 50MB 又不想缩小范围时，改用 C（EdgeOne）。

## B. 其他宿主自带的发布功能

例如 Claude 的 Artifact 发布（链接默认只有自己能看，由用户决定分享给谁）。

1. 先弄清楚这个功能的文件个数、单个文件大小和总大小上限，再按上限用 `--budget-mb` 生成副本。
2. 发布时保持目录结构不变：`index.html` 在根目录，`memories/…`、`music/…`、`flip.mp3` 作为同目录的附属文件。
3. 发布后打开链接核实：首页能打开，照片能加载。
4. 宿主对外部脚本有限制时，3D 可能加载不出来。这种情况就改用 C，并告诉用户原因。

## C. EdgeOne Makers（腾讯云）——没有自带发布、或体积太大时用

**先跟用户说清楚**：
> EdgeOne 要用腾讯云账号登录，并且账号完成**实名认证**，才能正式发布并长期保留；这些都由你自己在浏览器里完成。

不登录也能先发布，但链接 **60 分钟后失效**，要在 60 分钟内登录认领才能保留。

### C.1 准备（第一次）

**用到时才下载**：本 skill 不打包 EdgeOne 的任何文件，事先也不安装。只有用户明确同意发布到 EdgeOne 时，才去下载它的官方技能和命令行工具；只是在介绍平台、还没决定时，什么都不装。

1. 需要 Node.js 16 以上（`node -v`）。没有就请用户安装。
2. **问一次再安装**：
   > 要安装腾讯 EdgeOne 官方的部署技能和命令行工具来发布，可以吗？
3. 同意后运行：
   - `npx skills add TencentEdgeOne/edgeone-makers-tools`：官方技能，包含部署时必须遵守的规则；
   - `npm install -g edgeone@latest`：命令行工具，`edgeone -v` 要 ≥ 1.7.0。
4. **装好官方技能后，部署细节以它的规则为准。** 它的规则和下面写的冲突时，听它的。
5. 每次运行 `edgeone` 命令前，先 `export PAGES_SOURCE=skills`。

### C.2 生成副本、登录、部署

1. 生成副本：EdgeOne 单独用一个目录，里面会保存项目关联，重建时会保留，以后更新的是同一个项目：
   ```bash
   python3 $S/scripts/build_share.py --project ~/时光手帐 --out ~/时光手帐/share-edgeone
   ```
2. 检查登录：`edgeone whoami --json`。`true` 是已登录，`false` 是没登录，`null` 是查不到（这时停下说明原因，不要反复登录）。
3. 没登录时让用户二选一（选项文字照官方技能的写法）：
   - **登录后发布**（推荐，长期保留）：按官方技能的登录流程，打开浏览器登录；需要实名的，由用户在腾讯云控制台完成。
   - **直接发布，无需登录**：链接 60 分钟后失效，按官方技能的模板给出访问地址和认领链接。
4. 部署（在副本目录里运行）：
   ```bash
   cd ~/时光手帐/share-edgeone
   edgeone makers deploy -n <项目名> --json   # 第一次：先和用户确认项目名、工作空间
   edgeone makers deploy --json               # 以后：沿用 .edgeone/project.json 里的项目
   ```
5. 读取输出的**最后一行 JSON**：`url`、`projectId`、`consoleUrl`。
   - `url` 带着 `?eo_token=…&eo_time=…`，**必须完整给出**，少了后面这段会打不开（401）。
   - 把它单独放在回复最上面。
6. 告诉用户：
   - 这是预览链接；在国内访问，过一段时间或转发给别人后可能会受限。
   - 要长期稳定地公开访问，需要在 EdgeOne 控制台绑定自己的**已备案域名**。这一步需要实名，由用户自己操作。

`.edgeone/` 里是项目关联（用免登录方式认领后，还可能有登录信息）：
- 不要读取或展示里面的凭据；
- 不要把 `share-edgeone/` 拿去发到别的平台。别的平台用 `share/`。

## D. 飞书妙搭（用户明确要发到飞书时）

用飞书官方命令行 `lark-cli` 发布成一个 HTML 应用，链接是 `feishu.link`。打包后不能超过 20MB，所以用 `--budget-mb 19` 生成副本。

在豆包里运行时，不用走这一节：豆包自带的网页发布（A 节）也能发到妙搭，上限更大（50MB），也不用装 lark-cli。

### D.1 准备 lark-cli（第一次）

1. 运行 `lark-cli --version`。没装的话：
   - 没有 Node.js：请用户先安装；
   - 有 Node.js：问用户一次，同意后运行 `npx @larksuite/cli@latest install`。
2. **放后台**运行 `lark-cli config init --new`，把输出的授权链接**原样**发给用户，在浏览器里完成。
3. 登录：
   1. 运行 `lark-cli auth login --domain apps --no-wait --json`；
   2. 把 `verification_url` 原样发给用户，记下 `device_code`；
   3. 用户确认后，运行 `lark-cli auth login --device-code <device_code>`；
   4. 运行 `lark-cli auth status` 核实已经登录。

### D.2 发布

```bash
python3 $S/scripts/publish_feishu.py --project ~/时光手帐 --title "我们的时光手帐"
```

| 输出 | 怎么办 |
|---|---|
| `APP <app_id> new` / `reused` | 第一次发布会新建应用；以后复用同一个应用，链接不变 |
| `URL <链接>` | 发布成功。这是平台返回的真实链接 |
| `STILL_PUBLISHING` | 还在部署：过一会儿运行 `--resume` 继续查询 |
| `PENDING_APPROVAL [审批链接]` | 组织开了发布审批，要等审批负责人处理。处理完用 `--resume` |
| `FAILED <原因>` | 把原因转述给用户 |
| `OVER_LIMIT` | 用 `--budget-mb 19` 重新生成，或者改用 C |
| `NEED_LOGIN` / `NEED_INSTALL` | 回到 D.1 |

### D.3 谁能看

妙搭链接**默认只有创建者自己能打开**。问用户想让谁能看：

| 选项 | 参数 |
|---|---|
| 本企业 / 本组织 | `--scope tenant` |
| 所有人，但要先登录飞书 | `--scope public-login` |
| 所有拿到链接的人，不用登录 | `--scope public` |

- 输出 `SCOPE_WEB` 时，这类应用不能用命令行改可见范围。请用户在**妙搭网页端 → 我的应用 → 可见范围**里设置，不要反复重试。
- **删除应用**：先运行 `lark-cli apps +get` 把应用名和 app_id 给用户看；用户明确确认后，才运行 `lark-cli apps +delete --app-id <id> --confirm-name "<应用名>" --yes --as user`。

## 更新与撤下

- **更新**：用同样的范围参数重新生成副本，发布到**同一个**站点或应用，链接不变：
  - 豆包、宿主：按各自功能的更新方式；
  - EdgeOne：在 `share-edgeone/` 里运行 `edgeone makers deploy --json`；
  - 飞书：重跑 `publish_feishu.py`。
- **撤下**：在对应平台的控制台或网页端删除，或者收回可见范围。删除前先给用户看清是哪一个、征得明确同意。
- 都要提醒用户：别人已经存下来的照片收不回来。
